# Домашнє завдання до Теми 14: «Платформа під контролем»: що зроблено

Короткий звіт по кожному завданню: що змінено, де лежить результат і як його перевірити.

## Підготовка репозиторію

- Додано [.gitignore](.gitignore) з типовими правилами для Python: `__pycache__/`, `*.pyc`, кеші pytest/mypy/ruff, `.venv/`.
- У `.gitignore` також внесено локальні дані демо: `.keys/` (приватні ключі для підпису JWT), `audit.db` (журнал аудиту SQLite) і `.env`. Секрети та згенеровані дані не повинні потрапляти в Git.

## Завдання 1. Архітектурна діаграма

**Результат:** [diagram.png](diagram.png). Вихідний файл: [diagram.dot](diagram.dot) (Graphviz).

Перегенерувати діаграму:

```bash
dot -Tpng -Gdpi=130 diagram.dot -o diagram.png
```

Що показано на діаграмі:

| Вимога | Як позначено |
|---|---|
| Чотири рівні | Рівень 1 · ML (churn-predictor), Рівень 2 · LLM (RAG і пояснення), Рівень 3 · Агент (граф вузлів, guardrail, human approval), Рівень 4 · Платформа (API Gateway) |
| Шлях запиту | Синя лінія ①–⑥: клієнт → шлюз (authn) → **перевірка прав** (authz, виділено жовтим) → маршрутизація до сервісу → облік витрат → запис в аудит |
| Сховище аудиту | Окремий блок: append-only, `request_id`, `prompt_hash`, `customer_ref`; у демо SQLite, у проді ClickHouse/WORM |
| Місце підрахунку витрат | Блок «Облік витрат» (`cost.py`): токени → USD, бюджети орендарів; у проді Redis або ledger |
| Межі довіри | Червоні мітки: **TB1** інтернет → шлюз, **TB2** control plane → data plane (IdP, Git-політики, CI/CD), **TB3** агент → зовнішні MCP-інструменти |

Структура схеми відповідає еталону з [PLAYBOOK_UA.md](PLAYBOOK_UA.md) (п. 5). Діаграму намальовано в Graphviz, а не в draw.io чи Excalidraw: так вона зберігається як код, і її легко переглядати в PR.
